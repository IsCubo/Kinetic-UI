# kinetic-ui skill

Objective: a universal Agent Skill (agentskills.io format) for distinctive, accessible, device-aware frontend UX/UI with micro-interactions and advanced effects.
Branch: `feat/kinetic-ui-skill` (from `main`) · Delivery: `single-pr` (new solo repo, no remote yet; push/PR are the user's decision) · Test runner: `node --test tests/*.test.mjs` + `node scripts/validate.mjs skills/kinetic-ui`

## Specs

- **S1 Universal.** "quiero que ese plugin sea un conjunto universal que pueda ser utilizado por cualquier agente y con cualquier lenguaje". Acceptance: the skill follows the agentskills.io specification (`name` matches the directory, lowercase-hyphen, `description` ≤1024 chars, `SKILL.md` <500 lines, references one hop from `SKILL.md`). Guidance is framework-agnostic first, with per-platform sections (web, Flutter, SwiftUI, Jetpack Compose).
- **S2 Frontend UX/UI and patterns.** "esta skill quiero que esté enfocado en el frontend, priorizando las caracteristicas de un buen diseño ux/ui", "teniendo en cuenta patrones de diseño", "para los diferentes dispositivos que existen". Acceptance: foundations cover UX principles, UI design patterns, and responsive/device adaptation (input modes, screen classes).
- **S3 Micro-interactions and effects.** "basado en microinteraciones, efectos super interesantes también, ya sea como efectos parallax, scroll, de profundidad, 2d, 3d cyberpunk etc, en esa skill debe tener especificado eso". Acceptance: one reference file per effect family (micro-interactions, parallax, scroll-driven, depth, 2D, 3D/WebGL, …) and style files (cyberpunk, …).
- **S4 Component behavior.** "como funciona un componente". Acceptance: component files describe anatomy, states, timing, and micro-interactions.
- **S5 Brand identity.** "obviamente manteniendo la identidad de marca que se proporcione, si no hay, entonces sugerir en base al tipo de pagina o sentimiento a transmitir". Acceptance: a brand-intake procedure for a provided brand, plus an emotion/page-type → style mapping when there is none.
- **S6 Libraries.** "sugerir librerias funcionales y probadas para ese tipo de diseños, por ejemplo, conozco uno que es muy utilizado como three.js". Acceptance: a library catalog with verified package names, licenses, and caveats (sources cited, dated).
- **S7 Accessibility and low-end devices.** "apliquemos lo que me mencionaste tambien eso de prefers-reduced-motion y el fallback para moviles de gama baja". Acceptance: every effect and component file has mandatory `## Reduced motion` and `## Low-end fallback` sections, enforced by the validator; motion tiers T0–T3 with a detection snippet.
- **S8 Structure.** "y el tema de la estructura y demás". Acceptance: the proposed structure — short `SKILL.md` router, `references/`, `assets/`, a fixed reference template, and a validator.
- **S9 RAG-like index.** "dentro de la agent skill coloquemos como si fuera tipo rag ese decir que haya una referencia para que el agente sepa de una donde buscar sin necesidad de buscar en toda la estructura". Acceptance: an intent routing table in `SKILL.md` plus `references/INDEX.md`, a keyword catalog generated from each file's `Keywords` line. The validator fails when the index is stale or a path is missing.
- **S10 Location.** The user chose "Repo propio (Recommended)" with the proposed name `kinetic-ui` at `~/projects/kinetic-ui`.
- **S11 Direction.** The skill must decide before building: surface mode, visual world, and motion thesis, and emit a short brief the agent can follow. Acceptance: a workflow reference with inputs, steps, an output template, and anti-generic rules.
- **S12 Critique.** The skill must evaluate a rendered interface, not code alone, with a scored and evidence-based protocol. Acceptance: a scorecard with anchored dimensions, severity levels, a findings format, and a re-check loop.
- **S13 Verification.** The skill must prove the result works: functional states, keyboard and screen-reader access, contrast, reduced motion, motion tiers, and performance budgets, each with a how-to-test and a pass criterion. Acceptance: a verification matrix plus a runnable in-browser audit snippet.
- **S14 Loop.** The four stages must compose into one end-to-end workflow the agent can follow, with the artifacts each stage produces.
- **S15 Portable install.** The skill must install on any machine and any skills-compatible agent without a committed symlink or an absolute maintainer path. Acceptance: a cross-platform installer that resolves the target from the current user's home or project, copies by default, supports `--link` for development (junction on Windows), `--force`, `--dry-run`, and a generic `--dest`; tests cover copy, replace, link, dry-run, and target resolution; README documents it.
- **S16 Evals.** The skill must be measurable, not just plausible: a maintainer eval pack with realistic prompts, with/without-skill baselines, structured assertions, a workspace scaffold, and a grader that writes per-run and aggregate results. Acceptance: 4 cases, an intentionally flawed fixture for critique, `scripts/eval.mjs` (init/list/grade), tests, and a README that explains isolation and iteration.
- **S17 Tooling bridge.** The verify stage must route to the tools the runtime actually has — Playwright MCP, Chrome DevTools MCP, screenshots, Lighthouse, axe — with a default, a fallback, and an explicit BLOCKED state when none exists. Acceptance: a workflow reference with `## When to use` and `## Handoff`, linked from `verify.md` and the router, validated.
- **S18 Baseline isolation.** The without-skill eval baseline must be enforceable, not advisory: a local tool that moves every known installed copy out of the agent skills directories, writes a recoverable manifest, preserves symlinks, rolls back a partial hide, and restores after a failure; each run copies its inputs under `inputs/` so no prompt points back to the repository. Acceptance: `scripts/eval-isolate.mjs status|hide|restore`, 6 tests, and docs with strict container/profile, local hide/restore, and advisory levels.
- **S19 Assertion validity.** An eval assertion must test the behavior, not one implementation of it. Acceptance: `3d-fallback` accepts a CSS tilt answer as well as WebGL; the change is logged as post hoc and the baseline outcome for that assertion is unchanged.
- **S20 Blind quality lane.** Design quality must be measured apart from protocol vocabulary: anonymized A/B copies in random order with the key kept outside the review tree, a nine-dimension 0-4 rubric, and an unblind step that validates scores and reports per reviewer without touching the pass rate. Acceptance: `blind`/`unblind` commands, `evals/rubric.md`, tests for anonymization, reproducible seed, mapping, validation, and rubric/code drift.
- **S21 Reviewable artifacts.** Every eval run must produce something a reviewer can open without a toolchain. Acceptance: `RUN.md` requires one self-contained `.html` with inline CSS and JS, refuses a compile-step-only artifact as the sole output, and a test pins the requirement. Source: L29, where the baseline answered `operate-dashboard` in `.tsx` and the blind reviewer could not open it, so the cell was decided by default rather than by design.
- **S22 Functional reality check.** Critique must establish whether an interface actually works before judging how it looks, and an unrendered run must still report source-provable defects. Acceptance: `critique.md` runs the control-wiring check first, a closed list of source-provable facts carries severity without a render, an inert primary action is a blocker at any visual quality, and findings cite a capture id or the source location that proves them.
- **S23 SVG graphics.** "me gustaría agregar el tema de creacion especializada de svg tanto estaticas como dinamicas con movimiento a la skill de kinetic ui". Acceptance: a new effects reference covers static SVG craft (structure, optimization, theming, light/dark, accessibility) separately from the animation techniques `motion-2d.md` already owns (no duplication), with the mandatory `## Reduced motion`/`## Low-end fallback` sections, routed from `SKILL.md` and `INDEX.md`.

- **Assumptions (not yet confirmed by the user):** A1 the skill content is in English; A2 license Apache-2.0; A3 `metadata.author` is `IsCubo`.
