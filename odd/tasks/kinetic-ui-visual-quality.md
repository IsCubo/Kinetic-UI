# kinetic-ui visual quality

Objective: make the skill's output look and feel clearly better than without it — pages that hold attention, the requested 3D piece built to the stated dimensions, and the intended motion applied correctly — and prove it with rendered frames instead of vocabulary.
Branch: `feat/3d-depth` · Delivery: `ask-on-risk` · Test runner: `node --test tests/*.test.mjs` + `node scripts/validate.mjs skills/kinetic-ui`

## Specs

- **S1 Measure pixels, not words.** A zero-dependency capture script renders any local page and writes PNG frames plus a manifest, so a reviewer looks at the result instead of reading it. Acceptance: `scripts/capture-frames.mjs` drives a headless Chrome through the DevTools Protocol (no npm dependency, Node's built-in `WebSocket`), accepts `--chrome`, `--out`, `--url` (repeatable), `--viewport` (repeatable, default `360x800` and `1440x900`), `--steps` (default `0,0.25,0.5,0.75,1`), `--settle` and `--reduced-motion`; writes one PNG per page × viewport × step named `<name>-<width>x<height>-<pct>.png`; records `scrollY`, the scroll maximum, the `--kui-*` custom properties on the document element, JS exceptions and console errors per frame in `frames.json`; exits non-zero only when a capture itself fails (a page that throws is recorded, not fatal).
- **S2 The blind rubric scores what the user asked for.** "lo ideal es que en resultado, 'como se ve' se vea 100% mejor que sin skill, 'como se siente' sea wow esta pagina captó mi atencion". Acceptance: `evals/rubric.md` gains `impact` (does the first screen stop the eye and hold it, and is that attention earned by the content), `motion-fidelity` (does the motion feel like the brief asked for, and does it serve the content), and `3d-fidelity` (is the requested piece recognisable, correctly proportioned and believably lit), each with 0–4 anchors and an explicit note that frames, not prose, are the evidence.
- **S3 A real visual baseline before any claim.** Acceptance: the iteration-4 scroll-depth outputs are captured with the new script and reviewed frame by frame; the findings are recorded in `evals/README.md` with what the pages actually look like, including that neither run could see its own output.
- **S4 The skill looks at its own work.** "se capaz de entender el movimiento que se desea y lo aplique correctamente, con tecnica y visualmente mejor que sin skill". Acceptance: the skill's verify workflow requires capturing frames at the brief's key scroll positions and viewports, looking at them against the stated intent, and fixing what is visibly wrong, in at most two rounds; when rendering is impossible it must say which checks stayed unverified rather than implying a pass; the tooling reference documents the capture command and the failure modes that produce blank or unscrolled frames.
- **S5 Build the 3D piece the user asked for.** "que tambien sea capaz de crear con presicion esa pieza 3D que el usuario pida". Acceptance: a 3D reference teaches modelling a requested object with no supplied glTF — choosing primitives, lathe profiles, extrusions and bevels that match the object's real construction, real-world scale in metres, a declared list of measured versus invented dimensions, and a note that a recognisable silhouette beats polygon count; it names which existing 3D reference owns what and does not repeat it.
- **S6 Turn a described feel into parameters.** Acceptance: the motion reference maps a described intent or a cited reference ("suave", "energetico", "como en tal sitio") to explicit values — duration, easing family, distance, stagger, spring parameters — records the mapping in the motion thesis, and states what was inferred rather than shown.
- **S7 Prove it blind.** Acceptance: at least one eval case per new dimension (a 3D piece requested by description with no model, a page whose motion is described by feel), graded for protocol as today and reviewed blind on the new dimensions, with and without the skill; the review key stays outside the compared folders.
- **S8 Success definition (assumption, pending the user's acceptance).** In a blind A/B the user picks the skill's page in every case and it wins by at least one point on a 0–4 scale in `impact`, `motion-fidelity` and `3d-fidelity`.
